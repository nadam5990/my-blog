## `<div>` 천국에서 탈출하기

웹 개발을 처음 배울 때 `<div>`로 모든 걸 감싸는 습관이 생기기 쉽다. 나도 그랬다.
헤더든 메뉴든 본문이든 전부 `<div>`, `<div>`, `<div>`…

그런데 오늘 **HTML 시맨틱 태그(Semantic Tags)** 를 제대로 공부하고 나니,
그게 얼마나 아쉬운 선택이었는지 알게 됐다.

## 시맨틱 태그란?

시맨틱(semantic)은 '의미'라는 뜻이다.
시맨틱 태그는 태그 이름 자체가 *이 영역이 무엇인지* 를 설명해 준다.

| 태그 | 역할 |
|---|---|
| `<header>` | 페이지나 섹션의 머리말 |
| `<nav>` | 내비게이션 링크 모음 |
| `<main>` | 페이지의 핵심 콘텐츠 (페이지당 하나) |
| `<article>` | 독립적으로 배포 가능한 콘텐츠 (블로그 글, 뉴스 기사 등) |
| `<section>` | 주제별로 묶인 콘텐츠 구역 |
| `<aside>` | 본문과 간접적으로 관련된 사이드바 |
| `<footer>` | 페이지나 섹션의 꼬리말 |

## 코드로 비교해 보자

시맨틱 태그를 쓰지 않은 예시:

```html
<div class="header">
  <div class="nav">
    <div class="nav-item"><a href="/">홈</a></div>
    <div class="nav-item"><a href="/blog">블로그</a></div>
  </div>
</div>
<div class="main">
  <div class="article">
    <h1>오늘 배운 것</h1>
    <p>시맨틱 태그는 정말 중요하다.</p>
  </div>
</div>
<div class="footer">
  <p>© 2026 My Blog</p>
</div>
```

시맨틱 태그를 사용한 예시:

```html
<header>
  <nav>
    <a href="/">홈</a>
    <a href="/blog">블로그</a>
  </nav>
</header>
<main>
  <article>
    <h1>오늘 배운 것</h1>
    <p>시맨틱 태그는 정말 중요하다.</p>
  </article>
</main>
<footer>
  <p>© 2026 My Blog</p>
</footer>
```

코드 양도 줄고, `class="header"` 같은 이름을 따로 붙이지 않아도 구조가 한눈에 들어온다.

## 왜 쓰면 좋을까?

**1. 코드 가독성** — 태그만 봐도 각 구역이 무슨 역할인지 바로 알 수 있다.

**2. SEO(검색 엔진 최적화)** — 구글 같은 검색 엔진은 `<article>`, `<main>` 같은 태그를 보고
페이지의 핵심 내용이 어디에 있는지 파악한다. 시맨틱 태그를 잘 쓰면 검색 순위에 유리하다.

**3. 접근성(Accessibility)** — 스크린 리더(시각 장애인을 위한 도구)는 시맨틱 태그를 활용해
사용자가 `<nav>`로 바로 이동하거나 `<main>`으로 건너뛸 수 있게 해준다.
`<div>` 로만 만든 페이지에서는 이런 게 불가능하다.

## 느낀 점

솔직히 처음에는 "어차피 브라우저에 똑같이 보이는데 굳이 왜?" 라고 생각했다.
그런데 접근성 얘기를 듣고 생각이 바뀌었다. 내가 만든 페이지를 스크린 리더로 써야 하는
사람이 있을 수도 있다는 걸 잊고 있었다.

시맨틱 태그는 "화면에 어떻게 보이느냐"가 아니라 "이 콘텐츠가 무엇인가"를 표현하는 것이다.
앞으로는 습관적으로 `<div>` 를 치기 전에 "더 적절한 태그가 있지 않을까?" 를 먼저 생각해 봐야겠다.
