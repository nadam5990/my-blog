JavaScript를 공부하다 보면 `...`(세 개의 점)을 코드 곳곳에서 보게 된다. 이게 바로 **스프레드 연산자(Spread Operator)**인데, 처음엔 생김새가 낯설어서 "오타인가?" 싶었지만 알고 보니 정말 편리한 문법이었다.

## 스프레드 연산자란?

스프레드 연산자(`...`)는 배열이나 객체를 **펼쳐서** 그 안의 요소들을 꺼내주는 문법이다. 마치 봉투에서 편지를 꺼내는 것처럼, 배열이나 객체의 내용을 꺼내 다른 곳에 자연스럽게 넣을 수 있다.

## 배열에서 활용하기

### 배열 복사

```javascript
const fruits = ['사과', '바나나', '딸기'];
const copiedFruits = [...fruits];

copiedFruits.push('포도');

console.log(fruits);       // ['사과', '바나나', '딸기'] ← 원본 유지!
console.log(copiedFruits); // ['사과', '바나나', '딸기', '포도']
```

`=`로 그냥 대입하면 원본 배열도 함께 바뀌어 버리는데, 스프레드로 복사하면 완전히 독립적인 배열이 만들어진다.

### 배열 합치기

```javascript
const veggies = ['당근', '브로콜리'];
const food = [...fruits, ...veggies];
// → ['사과', '바나나', '딸기', '당근', '브로콜리']
```

`concat()` 없이도 여러 배열을 한 줄로 합칠 수 있어서 훨씬 읽기 편하다.

## 객체에서 활용하기

```javascript
const user = { name: '김철수', age: 25 };
const updatedUser = { ...user, age: 26 };

console.log(user);        // { name: '김철수', age: 25 } ← 원본 유지!
console.log(updatedUser); // { name: '김철수', age: 26 }
```

객체를 복사하면서 특정 속성만 덮어쓸 때 정말 유용하다. **나중에 나오는 키가 앞에 나온 키를 덮어쓰기** 때문에, `age: 26`이 기존 `age: 25`를 교체하고 새 객체가 만들어진다.

## React에서 더욱 중요한 이유

React에서는 `useState` 상태를 직접 수정하면 화면이 다시 렌더링되지 않는 버그가 생긴다. 스프레드 연산자로 새 배열·객체를 만드는 방식이 그 해법이다.

```javascript
const [todos, setTodos] = useState(['운동하기', '책 읽기']);

// 항목 추가 — 원본을 건드리지 않고 새 배열 생성
setTodos(prev => [...prev, '코딩하기']);
// → ['운동하기', '책 읽기', '코딩하기']

// 특정 항목만 수정
const [profile, setProfile] = useState({ name: '이영희', score: 80 });
setProfile(prev => ({ ...prev, score: 95 }));
// → { name: '이영희', score: 95 }
```

## 느낀 점

`...` 세 글자가 이렇게 넓은 활용 범위를 가질 줄은 몰랐다. 단순히 "복사하는 문법"이 아니라, **불변성(immutability)을 지키며 데이터를 안전하게 변형**하는 핵심 도구라는 걸 깨달았다. 특히 React 상태 관리에서 왜 스프레드를 써야 하는지 이유를 알고 나니, 이전에 겪었던 "상태를 바꿨는데 화면이 안 바뀌는" 버그의 원인도 이해됐다. 앞으로 `...`을 볼 때마다 든든한 친구처럼 느껴질 것 같다.
