# Git 브랜치로 작업 안전하게 분리하기

오늘은 Git의 핵심 개념 중 하나인 **브랜치(branch)**에 대해 공부했습니다.

## 브랜치란?

브랜치는 말 그대로 '나뭇가지'입니다. 기존 코드(메인 줄기)에서 갈라져 나온 독립적인 작업 공간이라고 생각하면 돼요. 새로운 기능을 개발하거나 버그를 고칠 때, 원본 코드를 건드리지 않고 별도의 공간에서 작업할 수 있습니다.

## 왜 브랜치가 필요할까?

메인 코드에서 바로 작업하다가 실수를 하면 전체 코드가 망가질 수 있습니다. 브랜치를 사용하면:

- 작업이 독립적으로 분리됩니다
- 실수해도 메인 코드에 영향이 없습니다
- 여러 사람이 동시에 다른 기능을 개발할 수 있습니다

## 기본 명령어

```bash
# 현재 브랜치 목록 확인
git branch

# 새 브랜치 만들기
git branch feature/login

# 브랜치로 이동하기
git switch feature/login

# 브랜치 만들고 바로 이동 (한 번에!)
git switch -c feature/signup

# 작업 완료 후 메인 브랜치로 돌아오기
git switch main

# 브랜치를 main에 병합하기
git merge feature/login

# 다 쓴 브랜치 삭제
git branch -d feature/login
```

## 실제 사용 예시

회원가입 기능을 새로 만든다고 가정해볼게요.

```bash
# 1. 새 브랜치 생성 후 바로 이동
git switch -c feature/signup

# 2. 코드 작성 후 커밋
git add signup.js
git commit -m "feat: 회원가입 폼 추가"

# 3. 메인으로 돌아와서 병합
git switch main
git merge feature/signup

# 4. 병합 완료된 브랜치 정리
git branch -d feature/signup
```

이렇게 하면 `main` 브랜치는 항상 안정적인 상태를 유지하고, 실험적인 작업은 별도 브랜치에서 안전하게 진행할 수 있어요.

## 브랜치 이름 짓는 팁

팀마다 다르지만, 일반적으로 많이 쓰는 규칙이 있어요:

| 접두사 | 용도 | 예시 |
|--------|------|------|
| `feature/` | 새 기능 개발 | `feature/login` |
| `fix/` | 버그 수정 | `fix/typo-in-header` |
| `hotfix/` | 긴급 수정 | `hotfix/payment-error` |
| `chore/` | 리팩터링, 설정 변경 | `chore/update-deps` |

이런 규칙을 따르면 브랜치 목록만 봐도 어떤 작업인지 바로 알 수 있어서 협업할 때 훨씬 편리합니다.

## 느낀 점

처음엔 브랜치가 왜 필요한지 와닿지 않았는데, 직접 써보니까 정말 편리하더라고요. 특히 혼자 작업할 때도 기능별로 브랜치를 나누면 작업 내용이 명확해져서 커밋 메시지 작성도 훨씬 쉬워졌어요.

`git switch -c` 명령어로 브랜치 생성과 이동을 한 번에 할 수 있다는 것도 새로 알았습니다. 앞으로는 아무리 작은 기능이라도 브랜치를 만들고 시작하는 습관을 들여야겠다고 생각했어요!
